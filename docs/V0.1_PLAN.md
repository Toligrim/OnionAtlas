# План реализации OnionAtlas v0.1

## 1. Цель релиза

v0.1 должна доказать, что архитектура работает end-to-end и может автономно поддерживать растущую базу без тяжёлой инфраструктуры.

Формула релиза:

```text
seed
→ persistent frontier
→ remote Tor worker
→ safe fetch
→ sanitized result
→ canonical import
→ SQLite
→ FTS5
→ link graph
→ new discovered onions
→ frontier
→ autonomous discovery sources
```

v0.1 не обязана быть красивым продуктом. Она обязана быть корректной, объяснимой и устойчивой.

---

## 2. Definition of Done

Релиз считается готовым, если выполнены все пункты:

1. control plane разворачивается на Linux одной документированной процедурой;
2. worker разворачивается на отдельном VPS;
3. worker использует только локальный Tor SOCKS;
4. seed можно добавить CLI/API;
5. seed попадает в persistent frontier;
6. worker получает lease и возвращает result;
7. result импортируется идемпотентно;
8. HTML очищается, текст и links извлекаются;
9. новый onion автоматически становится service + frontier target;
10. full-text search работает через FTS5;
11. входящие/исходящие service links доступны через API/UI;
12. offline targets получают retry/backoff;
13. после reboot frontier и retries сохраняются;
14. работает минимум один внешний discovery source помимо link discovery;
15. работает recrawl source;
16. считается novelty по discovery runs;
17. saturated source получает cooldown;
18. worker не имеет database credentials;
19. бинарные/медиа ответы не сохраняются;
20. 7-дневный autonomous soak test проходит без ручного пополнения frontier.

## 11. Фаза 8 — link discovery loop

Это первая настоящая автономность.

После каждого imported fetch:

1. извлекаются onion links;
2. canonicalize;
3. создаётся evidence;
4. неизвестные services создаются;
5. URL попадают во frontier;
6. scheduler выдаёт их worker.

### Acceptance

Из одного seed автоматически обходится граф глубиной минимум 2 без ручного добавления адресов.

## 13. Фаза 10 — external discovery adapter

Выбрать один разрешённый стабильный источник candidates.

Важно: adapter не должен определять canonical truth.

Pipeline:

```text
external candidate
→ discovery run
→ validate
→ dedupe
→ evidence
→ frontier
→ own crawl verification
```

### Acceptance

При пустом link frontier система способна автоматически получить новые targets из external source.

## 18. Фаза 15 — autonomous soak test

### Duration

Минимум 7 суток.

### Стартовые условия

- один control plane;
- один cheap worker;
- concurrency=2;
- ограниченный seed set;
- link discovery active;
- external discovery active;
- recrawl active.

### Во время теста запрещено

- вручную подкидывать адреса для поддержания роста;
- вручную чистить frontier;
- вручную перезапускать процессы кроме тестового reboot scenario.

### Проверяем

- uptime;
- restart recovery;
- database growth;
- new services/day;
- novelty;
- timeouts;
- memory;
- worker spool;
- disk;
- retries;
- source switching.

### Успех

Система продолжает crawl/discovery после первоначального запуска и сама восстанавливается после обычных временных сетевых ошибок/reboot.

## 20. Что НЕ делать в v0.1

Чтобы не утонуть в scope:

- не добавлять Playwright;
- не делать screenshots;
- не строить embeddings;
- не делать LLM agent;
- не ставить Elasticsearch;
- не ставить Redis/RabbitMQ «на будущее»;
- не создавать сложный SPA;
- не делать distributed database;
- не делать много типов внешних source сразу;
- не оптимизировать миллионные масштабы до измерений.

---

## 21. Приоритет реализации

Порядок важнее количества фич:

```text
correct persistent state
> safe fetch
> idempotent import
> autonomous link loop
> external discovery
> search/graph
> UI polish
```

Если vertical slice не надёжен, новые discovery sources только увеличат количество ошибок.

---

## 22. Первый milestone для coding agent

Первая практическая задача агенту:

> Реализовать минимальный vertical slice, который принимает 10 seed onion URL, хранит их в SQLite frontier, выдаёт задачи одному worker, fetch делает через локальный Tor SOCKS с concurrency=2, сохраняет безопасно нормализованный HTML-текст и ссылки, индексирует текст в FTS5 и автоматически добавляет найденные v3 onion URL обратно во frontier. Все операции должны переживать restart и иметь тесты на дедупликацию и идемпотентный import.

Не начинать UI и внешние discovery sources до прохождения этого milestone.
